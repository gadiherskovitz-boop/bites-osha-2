# Handoff — QSR Prospecting Engine, Hiring Signal Build

## Goal

Build a working prototype QSR prospecting engine for a GTM Engineer
take-home with Bites (mybites.io): signals in, tiered accounts, mapped
contacts, signal+tier-specific GTM motions, and one real personalized
first-touch — presented live as running software, not a deck. This
session's specific focus: **the OSHA signal path is functionally complete
except for one blocked dependency, so the build is pivoting to the Hiring
signal path**, which has no dependency on that blocker.

## Status

**The OSHA signal path is built and live-verified end to end, except for
contact resolution.** Everything upstream and downstream of contact
resolution works against the real HubSpot portal, real OSHA data, and a
real generated email:

- Signal scanning (OSHA `osha.gov/ords/imis`), tiering, brand-name
  collapsing, brand-wide history, and the `qsr_signal`/Note/Slack push are
  all done and live-verified.
- Tier 3 auto-enrollment into a real HubSpot Sequence: built, live-verified
  (real enrollment, real sequence, real connected inbox).
- Tier 1 personalized first-touch email: rules finalized, generation code
  built (Claude Sonnet 5), and the full delivery mechanism — draft written
  as a Note on the Contact, contact auto-enrolled in a dedicated Tier 1
  sequence — live-verified end to end against a real demo contact.

**The one missing piece is `resolve_contact` (Task #4)**: turning a signal
into a real named contact. This is blocked on **Amplemarket (Duo)** access
— the user is mid-signup on a business-domain trial. **Time-boxed**: if
Amplemarket doesn't grant a trial within a few hours, the user will fall
back to **Clay** (previously investigated and shelved for lack of an email
field — being reconsidered now as the fallback, not as a dead end).

**Decision made this session**: rather than wait idle on that one
dependency, **pivot to building the Hiring signal path**, which is
completely independent of Amplemarket/Clay/Task #4. The OSHA path isn't
abandoned — it resumes the moment contact resolution unblocks, and at that
point what's left (Task #4 itself, then Task #9's end-to-end dry run) is
mostly integration and verification of already-built, already-individually
-verified pieces, not new design work.

**Hiring signal status**: not started beyond persona-track definitions
(`pipeline/persona_tracks.py:HIRING_TRACKS`). No scanner, no tiering
integration, no signal handler wiring, no GTM motion built yet. The
`qsr-hiring-signals` Slack channel already exists.
