# Handoff — QSR Prospecting Engine, both signal paths largely complete

## Goal

Build a working prototype QSR prospecting engine for a GTM Engineer
take-home with Bites (mybites.io): signals in, tiered accounts, mapped
contacts, signal+tier-specific GTM motions, and real personalized
first-touch outreach — presented live as running software, not a deck.
Two independent signal sources feed it: OSHA enforcement data and job
postings (Hiring signal).

## Status

**Both paths are now largely complete and live-verified**, not
hypothetical. This session's own work was the Hiring path; a parallel
session (visible via shared commits, not tracked in detail here) closed
out the OSHA path's last open piece in the same window.

- **Hiring path** (this session): scans Greenhouse/Lever/Workday (7 known
  company boards) plus a keyword-based Adzuna discovery layer, tiers via
  the existing site_count waterfall, pushes real signals to HubSpot/Slack,
  and — via a manual Clay CSV enrichment bridge — creates real Contacts,
  drafts personalized emails, records GDPR consent, and enrolls in a real
  HubSpot Sequence. **22 real signals live across 13 real brands; 11 of 16
  Clay-enriched contacts fully processed end-to-end.** Full real-run
  detail (real IDs, every bug hit and fixed): `docs/hiring_workflow_walkthrough.md`.
- **OSHA path** (parallel session): Task #4 (contact resolution) and
  Task #9 (end-to-end dry run) reported complete via the same kind of Clay
  manual-CSV bridge — commit `73d97ce`, `docs/workflow_walkthrough.md`.
- **The real, shared discovery this session made**: Amplemarket (the
  originally-planned enrichment tool) never unblocked, and Clay's
  real-time script-callable path needs a paid plan neither session has.
  Both paths converged independently on the same workaround — a human
  exports a company-name CSV, enriches it in the Clay app UI, and hands it
  back for import — rather than the fully-automated `resolve_contact()`
  originally planned.
- `HANDOFF.md` and the original plan file
  (`/Users/ariherskovitz/.claude/plans/task-build-an-automated-parsed-rocket.md`)
  were both updated this session to reflect all of the above — read
  `HANDOFF.md` next, it's the authoritative living doc.
