# Handoff: QSR Prospecting Engine (Bites GTM Engineer Take-Home)

## Goal

Build a working prototype of a QSR prospecting engine for a GTM Engineer take-home assignment with Bites (mybites.io): signals in, tiered accounts, mapped contacts, signal+tier-specific GTM motions, and one real personalized first-touch — presented live in ~30 minutes as running software, not a deck. Code tracked on GitHub, built per `karpathy-coding-guidelines` (minimal, surgical, no premature abstraction).

- **Rung 5 (LLM tier classification) — done and verified live.** `pipeline/tier_classifier.py` uses **Claude Haiku 4.5 + web search** to place a brand in a tier *band* (not an exact count) — the reframing that makes an LLM rung cheap enough to be worth it: runs once per brand (not per signal), only for brands Rungs 1/4 miss, permanently cached (2.8–4.4s cold, 0.003s cached, **~$5 one-time for the whole 246-brand backlog**). Verified: Burger King (7,739), Pizza Hut (6,408), KFC (4,267), Dairy Queen (4,175) all correctly Tier 1 with accurate counts; Subway correctly short-circuits at Rung 4 with no wasted spend; a real single-location independent from our own scan is correctly declined, not hallucinated into a chain. Three operator decisions are baked in: **no source attribution** (not needed for this build), **round UP at band boundaries rather than discard** (`round_up_band()` — under-tiering a prospect costs more than over-tiering; note `value` is nulled when rounding, else `tier_for_lookup` would recompute the un-rounded tier and defeat the rule), and **Haiku not Opus** for cost. ⚠️ The Haiku choice required three model-specific changes that would each have failed on first run — basic `web_search_20250305` (the dynamic-filtering variant needs Opus 4.6+/Sonnet 4.6+), **no `effort`** (it errors on Haiku 4.5), and no `thinking`. Switching back to Opus means reversing all three, not just the `MODEL` constant. Skipped cleanly when no `ANTHROPIC_API_KEY` is set. **Measured against the real backlog** (14-name sample of the 243 Rung-1 misses): ~29% resolve, extrapolating to ~70 brands and ~50 Tier 1 accounts currently stuck at Tier 3. `Ayvaz Pizza Llc Dba Pizza Hut` → Tier 1 shows the DBA collapse and Rung 5 composing correctly; `Tim Hortons 7479` → 691 correctly excludes ~3,500 Canadian locations. **Known limitation:** opaque legal-entity/franchisee names (`Ssb Eastern, Llc`) mostly decline to the Tier 3 default — correct failure mode, but Rung 5 does *not* solve franchisee identity.
